## 2. Chuẩn hóa để bán hosting

### Quy ước sản phẩm

Một WHMCS service = một SNPanel hosting account.

Mapping chuẩn:

| WHMCS | SNPanel |
|---|---|
| Service ID | `external_id = whmcs:{serviceid}` |
| Client email | `User.email` |
| Hosting username | `User.username`, ví dụ `bp_12345` |
| Service password | Panel/SFTP password |
| Domain | Primary `Website.domain` |
| Product package | `UserPackage.id` |
| Suspend | disable web + SFTP + cron + terminal |
| Terminate | delete website/user/database/backups theo policy |

## 3. Thiếu cần làm trước khi bán

### Bắt buộc

1. **Provisioning API riêng**

2. **Bảng link billing**
   - Thêm model: `ProvisioningAccount`.
   - Lưu `external_id`, `user_id`, `primary_website_id`, `package_id`, `status`.

3. **Suspend thật**
   - Hiện `Website.status = suspended` chỉ là data, chưa chắc Nginx/SFTP/cron bị khóa.
   - Cần suspend vhost, PHP-FPM pool, cron, SFTP login, terminal.

4. **Quota thật**
   - Hiện storage quota là soft quota app-level.
   - Bán hosting nên thêm OS quota theo `/home/<user>`.
   - Ubuntu 24.04 dùng filesystem quota/project quota tùy ext4/xfs.

5. **Giới hạn theo gói**
   - Hiện package chỉ có website/storage.
   - Cần thêm:
     - `database_limit`
     - `alias_limit`
     - `backup_retention_days`
     - `terminal_enabled`
     - `waf_enabled`
     - `wordpress_enabled`

6. **Usage API**
   - WHMCS cần lấy disk usage.
   - Sau này thêm bandwidth từ Nginx logs.

## 5. Thiết kế SNPanel provisioning API

### Auth

Header:

```text
Authorization: Bearer <snpanel_api_token>
```

Token lưu DB dạng hash:

```text
ApiToken:
  id
  name
  token_hash
  scopes
  allowed_ips
  is_active
  last_used_at
  created_at
  revoked_at
```

### Account payload

```json
{
  "external_id": "whmcs:12345",
  "username": "bp_12345",
  "email": "client@example.com",
  "password": "generated-password",
  "package_id": 2,
  "domain": "example.com",
  "php_version": "8.4",
  "app_type": "php",
  "install_wordpress": false,
  "enable_ssl": true
}
```

### Idempotency rule

`POST /accounts`:
- Nếu `external_id` đã tồn tại và active: trả account hiện có.
- Nếu đang pending: trả pending.
- Nếu failed: cho retry có cleanup an toàn.
- Không tạo trùng user/domain.

## 6. Thiết kế WHMCS module

### Server config trong WHMCS

| Field | Dùng cho |
|---|---|
| Hostname | `panel.example.com` |
| Port | `2222` |
| Secure | Yes |
| Access Hash hoặc Password | SNPanel API token |

### Product config options

| Option | Ví dụ |
|---|---|
| `Package ID` | `1`, `2`, `3` |
| `App Type` | `php`, `static`, `wordpress` |
| `PHP Version` | `8.4` |
| `Install WordPress` | `yes/no` |
| `Auto SSL` | `yes/no` |
| `Terminal Enabled` | `yes/no` |

### CreateAccount flow

1. Build `external_id = whmcs:{serviceid}`.
2. Build username `bp_{serviceid}`.
3. Call `POST /api/provisioning/v1/accounts`.
4. Save returned panel URL/IDs into WHMCS service notes/custom fields.
5. Return `success` or error string.

### Suspend flow

Call:

```text
POST /api/provisioning/v1/accounts/whmcs:12345/suspend
```

Payload:

```json
{
  "reason": "Invoice overdue"
}
```

### Terminate flow

Call:

```text
DELETE /api/provisioning/v1/accounts/whmcs:12345?backup=true
```

Policy đề xuất:
- Tạo full user backup trước.
- Xóa website/database/user.
- Giữ backup 7 ngày.
